# A案「旧UI進化型」試作

## v2の試作方針

v1を保持し、`/prototype-a/cpu-v2.html` と `/prototype-a/online-v2.html` にv2を追加する。独立したv2.cssで利用可能な高さを三つの列へ配分し、カード幅96px、HP/AP12pxを維持する。収納中も手札の名前・コスト・HP/APのプレビューを残す。展開時は手札の高さを増やす。カード名・現在値は実画像の上にパネル表示し、詳細は既存のモーダルで読む。枚数による縮小は行わない。

比較は同一状態の旧UI・v1・v2で実測し、375×667と375×560で文書・盤面内の縦スクロール量、三領域の座標、HP/AP文字サイズ、10体・14枚の横スクロールを検証する。CPU/オンラインの選択・使用・再接続を既存接続層で確認する。Engineとオンライン接続層はv1から変更しない。

検証コマンドは `node --test prototype-a/v2-e2e.cjs`。画像と `v2-metrics.json` を専用Actionsの成果物に出力する。ローカルの既定出力先はシステム一時フォルダーの `mushi-a-v2-evidence-20261112`。

## 設計・実装計画

基準は main の c916fef。添付の森・滝・深緑・金色を参考に、116px幅の実カードと明瞭なHP/APを中心にする。枚数による縮小をやめ、場と手札を独立した横スクロールにする。小さい画面では盤面全体を縦スクロールし、主操作を画面下に固定する。空の場は小さくする。

1. 旧UI・B案を同じ状態・画面サイズで撮影し、カード実測値を記録する。
2. 共通boardに省略可能な見出し・手札初期表示オプションを追加し、A案ページだけで使用する。
3. 専用CSSとローカル試作サーバーを追加する。CPU・オンラインの既存アダプター、実カードDB・画像・ルールを利用する。
4. 375×667、375×560、スマホ横向き、PCで、多数展開・空盤面・手札・詳細・実操作を検証する。
5. 比較画像と結果を記録し、ドラフトPRで評価を待つ。

## 起動

Node.js 24以上と既存server依存のwsが必要。リポジトリルートで `node prototype-a/server.cjs` を実行し、表示された `http://127.0.0.1:8820/prototype-a/` を開く。ポート使用中なら起動を中止する。別ポートは `node prototype-a/server.cjs 8821`。停止はこのプロセスのCtrl+C。

ローカルCPUとローカルWebSocket APIを同じポートで起動する。A案ページのHTMLは既存index.html / online-b.htmlから生成し、専用CSSと表示オプションだけを追加する。比較用の旧UI・B案も同じローカルサーバーで開ける。静的配信は必要なブラウザ資産のみを許可する。

共有boardへの変更は既定値で無効の表示オプションのみ。Engine・AI・通信仕様・保存形式は既存のものを使用する。公開時の配信設定への組み込みは、この試作の承認後に検討する。

## 比較と検証

2026-11-11、375×667の同じ実カード構成で測定。

| 表示 | 自分の場のカード幅 | 画像領域 | HPの文字 |
| --- | ---: | ---: | ---: |
| 旧UI | 76px | 74×104px | 11px |
| B案 | 約94px | 約94×132px | 10px |
| A案 | 116px | 114×160px | 14px |

旧UIは場4体を同時に見やすい。B案は高さを画面内に配分する。A案は横に約2.8体が見え、隣のカードを横スワイプで確認する。10体でもカード幅を維持する。カード画像と数値を拡大する代わりに、SE3では盤面全体を縦スクロールする。手札は表示・収納できる。空の場は小さくなる。

ローカルChromiumでCPU・オンライン操作2/0、full 2132/0、shared 80/0、サーバー関連19/0。Linuxの専用ActionsでChromium・WebKitのCPU・オンライン4/0を確認した。CPU攻撃時の縄張り選択を解決して次の自分のターンへ進む経路も追加確認する。スクリーンショットとmetrics.jsonは専用Actionsの `a-prototype-screenshots-and-metrics` 成果物に保存される。

検証サイズは375×667、375×560、667×375、1280×800。3対4・手札4、5対5・手札6、10体・手札14、空の場、詳細と対象選択を検証する。375×1200は構成全体の参考画像で、SE3相当画像とは区別する。実カード画像は既存の共通マニフェストと描画部品を使用する。

母艦PCではEdgeが終了し、WebKitのダウンロードもタイムアウトしたため、ChromeとLinux上のWebKitで検証した。iPhone Safari実機のスワイプ感覚・ブラウザバー・セーフエリアは確認待ち。大きなカードを保つ方式での縦スクロール量が主な評価点となる。
