# Battle 1画面レイアウト：実機レビュー待ち

2026-09-20。基点 `fb72ea6`、作業ブランチ `astra-ui-redesign`。
添付「蟲神器 Battle 1画面完結レイアウト案」を確認し、情報配置の思想を採用。既存の深緑・生成り・金のデザインを維持した。

## 原因・採用構造

従来はカード3領域の最低高に加え、52pxヘッダー、44pxのステータス2行、38pxログ行、可変高の説明・操作欄を積んでいた。カードを潰さないため、合計がviewportを超えるとBattle rootを縦スクロールしていた。

今回は本文の高さを `dvh` とsafe areaで確保し、ログの専用行を撤去。ステータスを各32pxの1行表示にまとめ、説明は1行の要約＋タップで全文を表示する。

- **Portrait**：ヘッダー／相手ステータス／相手の場／自分の場／自分ステータス／手札／操作。カードは最低76×106px。高さ800px以上の縦画面は従来の場82×114px・手札88×123pxを維持。
- **短いPortrait**：safe areaを除いた高さ552px未満では重複する場の見出しを省き、余白を圧縮。カードサイズは変えない。
- **Landscape**：相手の場を上、自分の場と手札を下に配置し、操作は右rail。使用可能高さ360px未満では、相手の場・自分の場・手札を横3領域にして同時表示。
- **横スクロール**：場・手札とも1列。左右ボタンは、その方向に隠れたカードがあるときだけ表示。スワイプ・ボタン両方で移動可能。
- **詳細**：ログと技／色の選択はnative dialog。操作説明・チュートリアル全文もdialog。ヘルプ・設定・カード詳細・縄張り選択は既存の操作を維持。
- **ターン終了**：操作欄に位置を保持。Engineが許可しないフェイズは無効表示。CARD_SELECTION中の既存「選択を決定」動作を維持。
- **ナビ**：Battleには従来から下部ナビがない。今回も新設せず、Homeの下部ナビをそのまま維持。カード領域と対戦への集中を優先した。
- **fallback**：使用可能高さがportrait 518px未満／landscape 234px未満、または極端に狭い場合のみBattle rootの縦スクロールを許可。カードを潰さない。

## 変更ファイル・ロジック保護

- `index.html`：Battle専用CSS／表示adapterを読み込む。
- `css/battle-compact.css`：1画面構成、ステータス、横送り、drawer、縦横切替。
- `js/ui/battle-compact.js`：既存DOMとイベントを保持して再配置。表示更新・サイズ測定・dialog開閉・スクロールだけを担当。
- `js/ui/battle-experience.js`：ヘルプの配置説明を更新。
- `tests/astra-responsive.cjs`、`tests/astra-browser.cjs`、`tests/astra-compact-actions.cjs`：表示・操作の回帰確認。

Battle Engine、CardDefinition、カード効果、CPU、デッキルール、501枚catalog、保存形式、Toolbox→Battle handoffは変更していない。製品の表示adapterからGameStateを書き換えていない。テストのみ、枚数や代替召喚の条件をfixtureとして設定する。

## iPhone実機の最終判定

**実装・自動確認は完了。人間による実機Safariの承認は未完了。** merge／pushは行わない。

1. SafariのURLバー表示・収納の両方で、場・手札・ターン終了が同時に見えること。
2. 縦横を何度か回転し、ノッチやホームインジケーターに重ならないこと。
3. 場8体・手札12枚をスワイプ／左右ボタンで移動し、カードを誤操作しないこと。
4. コンパクトなステータスが読め、エサ・捨て場などを指で開きやすいこと。
5. 技選択・代替召喚・縄張り選択・ログを開閉し、閉じた後に盤面操作へ戻れること。
6. チュートリアルの要約から全文を開け、通常対戦でも操作案内が分かること。

既知の制約：実機Safariのブラウザバーのアニメーションとタッチ感は未検証。WebKitのdesktop実行・safe areaの疑似値は実機そのものではない。極端に小さい表示領域はfallbackとして縦スクロールする。画像取得は既存どおり外部配信に依存する。ステータスの略称と32pxの行高は、実機で読みやすさ・押しやすさを確認して調整する余地がある。
