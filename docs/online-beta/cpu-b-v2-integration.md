# CPU B v2 integration
Baseline bbcac2e. Existing Toolbox storage key/format, deck setup, GameEngine, CpuAgent and CpuRunner are preserved. CPU sessions default to the same MushiBattleBoard and presentation module used online. battleUi=legacy keeps Astra; an in-game menu switches views without starting a second engine. Hotseat/tutorial keep their existing UI.

Engine projection and capability resolver moved verbatim from server/lib/gateway.cjs to battle-ui/engine-view.js with only a browser/CommonJS wrapper and cryptographic random-ref provider. Server gateway reexports it. No files in js/engine or card definitions change in substance, and normalized Engine/card contract remains identical. CPU adapter validates issued commands against a snapshot, executes Engine functions on a clone and updates the existing facade. AI runs through the existing CpuRunner. CPU never connects to game WebSocket. Host Kaspersky browser protection injects its own separate socket; tests report that separately without changing antivirus settings.

Controller wraps existing setup/render/replay lifecycles. Legacy action dialog MutationObserver is suppressed only while CPU B owns presentation; its close event must not cancel a B-owned pending effect. Reproduced browser failure and fixed in js/ui/battle-compact.js.

Tests: tests/cpu-b-adapter.test.cjs covers hidden cards, invalid/stale capability rejection, atomic preservation and restoration. server/browser/cpu-b.cjs covers real Toolbox handoff, both decks, cards/detail, mobile/landscape/desktop, legacy switch, two full games and replay in each browser. cpu-b-effects.cjs covers two attack skills, sacrifice variants, target selection, variable cost after a real target selection, JSON restore and continued resolution, 10 units/14 hand cards and horizontal overflow. Existing Astra browser tests explicitly select battleUi=legacy with original assertions retained. B default paths are covered by new tests.
