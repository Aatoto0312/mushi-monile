# 蟲神器マニュアル v0.1

> 目的: OpenCode / Qoder / Codex などの実装AIが「一般的なTCGの常識」で蟲神器を補完せず、蟲神器固有のルールを参照して実装するための基準文書。
>
> 対象: スターターセット + 第1弾実装の基礎。
>
> 最終更新: 2026-08-31

---

## 0. 最重要原則

### 0.1 推測禁止

蟲神器の仕様が不明な場合、他TCGの慣例・類似ゲーム・一般的なカードゲーム知識から推測して実装してはいけない。

不明点は必ず以下のどれかで管理する。

- `VERIFIED_OFFICIAL`: 公式サイト、公式Q&A、公式カード画像、公式ガイドで確認済み
- `VERIFIED_SECONDARY`: 非公式DB等で確認済み。一次資料での再確認余地あり
- `PROVISIONAL`: 仮仕様。公式裁定ではない
- `BLOCKED`: 根拠不足。実装してはいけない

### 0.2 参照優先順位

1. 公式カード画像・現物カード
2. 蟲神器公式サイト「遊び方」
3. 蟲神器公式Q&A
4. 公式ガイドブック等
5. 非公式カードDB / Wiki
6. コミュニティ情報

下位資料と上位資料が矛盾する場合は、上位資料を優先する。

### 0.3 コードより仕様書を優先

既存コードと本書が矛盾する場合、「既存コードが正しい」と仮定してはいけない。
差分を報告し、一次資料で確認する。

# 1. カードの構造

蟲神器には以下の3種類がある。

- 虫カード
- 強化カード
- 術カード

カード左上の数値はコスト。

## 1.1 虫カード

虫カードでは最低限、以下を別々のデータとして保持する。

- カード名
- カード番号
- レアリティ
- 色
- コスト
- 体力（HP）
- 技名
- 技の攻撃力（AP）
- 技効果
- `＜○○＞` 表記の特性
- 特性効果
- カード下部の解説
- 生物分類（○○目、○○科など）
- 公式裁定
- 出典

### 1.1.1 `＜○○＞` は特性として扱う

`＜りんぷん＞`、`＜とびだす＞`、`＜擬態＞` などの `＜○○＞` 表記は、本プロジェクトでは「特性」として独立管理する。

ただし「特性だから同じ種類の処理」と考えてはいけない。

特性はカードごとに、

- 常在
- 条件付き
- 誘発
- 場に出た時
- 縄張りから引かれた時
- ターン限定
- 攻撃対象制限
- その他特殊処理

など挙動が異なる。

特性名だけを見て効果を推測してはいけない。必ずカード本文と裁定を確認する。

### 1.1.2 解説はフレーバーテキスト扱いしない

虫カード下部の「解説」には `カマキリ科`、`セミ科`、`アゲハチョウ科` などの生物分類が記載される。

後の弾では「○○科の虫」を参照する効果が存在するため、解説全文を単なる表示文として保存するだけでは不十分。

最低限、

```yaml
biologicalNote:
  rawText: "カード下部の解説全文"
taxonomy:
  order: null
  family: "カマキリ科"
  other: []
referencableTags:
  - "カマキリ科"
```

のように、全文と構造化データを両方持つ。

**分類は知識から補完しない。カード記載または公式資料で確認したものだけ登録する。**

# 2. デッキとゲーム準備

- デッキは20枚。
- デッキをシャッフルする。
- 縄張りを裏向きで6枚置く。
- 初期手札を4枚引く。
- 先攻・後攻を決める。
- 先攻プレイヤーの1ターン目はドローしない。

初期状態の目安:

```text
Deck: 10
Hand: 4
Territory: 6
Food: 0
Field: 0
Discard: 0
```

---

# 3. ゾーン

各プレイヤーは最低限以下を持つ。

- `DECK`
- `HAND`
- `TERRITORY`
- `FOOD`
- `FIELD`
- `DISCARD`

強化カードは場の虫に装着されるため、実装では `attachments` を虫インスタンスに持たせてもよい。

裏向き状態は「ゾーンを離れた」ことと同義ではない。

---

# 4. ターン進行

基本ターンは以下。

1. ドローフェイズ
2. セットフェイズ
3. メインフェイズ
4. ターンエンド

## 4.1 ドロー

通常は山札から1枚引く。

先攻1ターン目はドローしない。

## 4.2 セットフェイズ

手札からカードを **0枚または1枚** エサ場へ置ける。

- エサセットは強制ではない。
- 虫・術・強化のどの種類でもエサにできる。
- 通常のエサセットはセットフェイズのみ。
- メインフェイズに入った後、通常ルールで追加セットはできない。

## 4.3 メインフェイズ開始時のコスト

メインフェイズ開始時、エサ場にあるエサの枚数と同じ数のコストが発生する。

重要:

```text
food.length != availableCost
```

エサは基本的に支払いで消費しない。
コストはカード使用時に減る。
未使用コストはメインフェイズ終了時に消滅し、次ターンへ持ち越さない。

メインフェイズ中に効果でエサが増減しても、すでに発生したコストを単純に再計算してはいけない。

---

# 5. メインフェイズ中にできること

必要な条件を満たす限り、好きな順番で繰り返せる。

- 虫を場に出す
- 虫で攻撃する
- 強化カードを使う
- 術カードを使う

場に出せる虫の数に上限はない。

虫は場に出したターンから攻撃できる。

通常、1つの虫につき1ターン1回まで攻撃する。
ただしカード効果による例外がある。

---

# 6. 技

虫で攻撃するときは、その虫が持つ技を選ぶ。

技が2つある場合は、どちらを使うか選択する。

技は最低限、

```yaml
name:
baseAp:
effectText:
additionalCost:
usageLimit:
targetRule:
timing:
```

を分離して管理する。

`AP 0` の技も合法な技でありうる。

APが効果でマイナスになっても内部数値はマイナスのまま保持する。
攻撃時の最終ダメージは0未満にならない。

例:
AP -100 に `天牛の大顎` +300 → AP 200。

---

# 7. 攻撃対象

## 7.1 基本

相手の場に合法な攻撃対象の虫がいるなら、その中から1体を攻撃する。

相手の場に合法な攻撃対象がいないなら、相手プレイヤーへの直接攻撃になる。

「虫が場に存在すること」と「その虫を攻撃対象に選べること」は分けて判定する。

例:

- 裏向きで「いないものとして扱う」虫
- `＜擬態＞` 発動中の虫
- `＜りんぷん＞` 等による対象制限

これらは個別に合法対象判定を行う。

## 7.2 重要: 直接攻撃時に縄張りを選ぶのは防御側

公式ルールでは、直接攻撃を受けたプレイヤーが、自分の縄張りから裏向きのまま好きなカードを1枚選び、手札に加える。

したがって、実装UIは

```text
攻撃側: 虫 + 技を選び、直接攻撃を宣言
↓
防御側: 自分の縄張りのうち1枚を選択
↓
選んだ縄張りを処理
```

とする。

**攻撃側が「どの縄張りを殴るか」を選ぶ実装にはしない。**

ただし、縄張り6枚を独立したCardInstanceとして表示し、防御側が実際に1枚を選ぶ体験は残す。
この選択が `＜とびだす＞` 等の運・判断要素につながる。

---

# 8. 縄張り

縄張りは単なるライフ数値ではない。
各縄張りを独立した裏向きカードインスタンスとして保持する。

以下の場合、攻撃を受けた側が縄張りから裏向きのまま好きな1枚を選び、手札に加える。

- 虫の攻撃によって自分の虫が破壊された
- 相手から直接攻撃を受けた

術や強化等の効果だけで虫が破壊された場合は、原則として縄張りを引かない。

## 8.1 縄張り0枚

相手の縄張りが0枚でも、相手の虫を攻撃して破壊しただけでは勝利にならない。

縄張り0枚の相手へ **直接攻撃が成立した時** に勝利。

---

# 9. `＜とびだす＞`

スターターではミンミンゼミが持つ。

縄張りから引いた時、自分の場に `＜とびだす＞` を持つ虫がいなければ、場に出してよい。

重要:

- 縄張りから選ばれたカードそのものを見て判定する。
- 単に `territoryCount--` で済ませてはいけない。
- 裏向きで「いないものとして扱う」虫は、場の `＜とびだす＞` 所持判定を妨げないという公式裁定がある。

---

# 10. 色と属性相性

スターター〜第1弾の基本色:

- 赤
- 青
- 緑

有利関係:

```text
赤 → 緑
青 → 赤
緑 → 青
```

有利色へ攻撃する場合、ダメージ2倍。

それ以外は1倍。

**0.5倍の不利補正は存在しない。**

属性倍率は、APの増減を適用した後の攻撃力をもとにダメージへ適用する。

---

# 11. ダメージと破壊

虫はHPが0以下になると破壊され、捨て札へ移動する。

攻撃力に一時修正がある場合:

1. 技の基本AP
2. AP修正
3. 最終AP
4. 色倍率
5. 最終ダメージ（最低0）

という考え方を基本とする。

効果付き攻撃は、特に記載がなければ **技効果を解決してからダメージ**。

---

# 12. ターン終了

ターン終了時:

- 虫が受けていたダメージをすべて回復
- 「ターン終了時まで」の効果を終了
- 残ったコストを消滅
- 次のプレイヤーへ交代

カード効果による期限付き状態は、その効果ごとのタイミングで解消する。

---

# 13. 強化カード

強化カードは虫につけて使用する。

実装では最低限、

```yaml
hostInstanceId:
attachmentInstanceId:
effects:
```

を追跡する。

ついている虫が場を離れた場合、その強化カードの処理をカードルールに従って行う。

「裏向きになる」ことは場を離れることではないため、場を離れた時のクリーンアップを発火させない。

---

# 14. 術カード

術カードは使い切りで効果を発揮する。

解決時に対象が必要なカードは、合法な対象が存在しなければ使用できない場合がある。

例: `塵芥虫の爆熱弾` は相手の虫を選ぶ必要があるため、相手の場に合法対象がなければ使用できない。

---

# 15. スターター重要特性

## 15.1 `＜りんぷん＞`

ナミアゲハ。

相手は、その `＜りんぷん＞` を持つ虫以外を攻撃できない。
複数いる場合は、その中から選んで攻撃する。

これは虫の攻撃先を制限する。
術カードの対象制限とは別。

## 15.2 `＜擬態＞`

ナナフシモドキ。

カード記載:
「これは場に出た次の相手のターンに攻撃を受けない。※これ以外に虫がいないとき、直接攻撃を受ける。」

発動中の擬態虫しか攻撃対象候補がいない場合、直接攻撃になる。

術カードは擬態の影響を受けず、別途カードの対象条件に従う。

## 15.3 `＜とびだす＞`

ミンミンゼミ。

縄張りから引いた時に発揮する条件召喚系特性。

# 16. スターター重要カード裁定

## 16.1 オオカマキリ / カマ連撃

- AP 200
- 攻撃後、相手の場に虫がいれば、もう一度だけ使用できる
- 最大2回
- 2回目は1回目の攻撃直後
- 他行動を挟まない
- `天牛の大顎` のAP+300は両方に適用
- 1回目で相手最後の虫を破壊し、攻撃終了時点で場に虫がいなければ2回目なし
- 1回目の結果として `＜とびだす＞` で虫が場に出た場合、条件を満たせば2回目可能
- 裏向きで「いないものとして扱う」虫だけの場合は継続条件を満たさない

## 16.2 オオカマキリ / 共食い

- AP 800
- 使用時、この虫以外の自分の虫1体を選び破壊する
- 適切な自分の虫がいなければ使用不可
- これは攻撃ダメージによる破壊ではなく、技を使用するための条件としての破壊

## 16.3 カブトムシ / すくい投げ

- AP 0
- 相手の虫1体を選び、ターン終了時まで裏返す
- 裏向きの間、その虫はいないものとして扱う
- 裏向きはFIELD離脱ではない

## 16.4 セアカゴケグモ / 毒針

- AP 400
- 場を離れるまで1度だけ使用可能
- 別個体の同名カードには影響しない
- 場を離れて再度場に出れば再使用可能

## 16.5 ナミアゲハ（幼虫） / くさいツノ

- AP 0
- 相手の虫1体を選ぶ
- 次のターン、その虫の攻撃力を400下げる
- APは数値上マイナスになりうる
- マイナスAPによる攻撃ダメージは0
- 裏向きになっても、場を離れていないため修正は消えない

カード図鑑側の推奨形式:

```yaml
officialNumber:
name:
set:
starterDeck:
rarity:
type:
color:
cost:
baseHp:

skills:
  - name:
    baseAp:
    effectText:
    usageLimit:
    targetRule:
    timing:

traits:
  - name:
    rawText:
    timing:
    effectType:
    rulings: []

effectText: null

biologicalNote:
  rawText: null

taxonomy:
  order: null
  family: null
  other: []

referencableTags: []

rulings: []

sources:
  cardData:
  biologicalNote:
  rulings:

verification:
implementationStatus:
blocked: []
```

`skills` と `traits` を混同しない。
`biologicalNote.rawText` と `taxonomy` も混同しない。
